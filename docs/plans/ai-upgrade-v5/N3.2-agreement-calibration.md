# N3.2 — Visual agreement calibration (`awkit-vra.4.2`)

Measured on 2026-10-13, Windows 10, bundled Playwright Chromium, against the N3.1 policy `decideVisualAgreement`
(`9f32bc07`). The verdict: **the acceptance fails. 28 twins decisions reached `agreed` with the DOM best on the
remembered position, so N3 closes shadow-only and N3.4 (enforce) and N3.5 (provenance) are deferred**, as the plan
fixed in advance ("If N3.2 shows any false `agreed` … N3 closes shadow-only"). N3.3 (runner shadow) and N3.6 remain.

## Lab

`/visual-intelligence/fusion`, the Visual Fusion Calibration Lab (`mock-site/public/visual-intelligence-fusion.html`,
documented in `mock-site/README.md`). N3.2 added two things and changed nothing else:

| Addition | What it is |
|---|---|
| `drift` scenario | The target alone gets `id="vf-drifted"`, `data-drift="renamed"` and the accessible name "Delete selected item" instead of "Item action". Classes, style and icon are unchanged, so its pixels match the baseline and only its DOM evidence moved. |
| Wide toolbar `vf-wide-toolbar` | `setState({ wide: true })` shows nine 48x40 buttons `vf-wide-tool-0`…`-8` at (92, 470), each with a distinct icon (all trash under `twins`). It exists so a decision can carry 8 competitors, the VR-4 cap. Hidden by default, so every earlier scenario renders exactly as before. |

`describe()` also returns `names` (the accessible names) and `wideIcons`. `verify:mock-site` covers both additions
(307/307).

## Method

`npm run benchmark:visual-agreement` (`scripts/benchmark-visual-agreement.mts`, informational, never a gate). For
each DPR in {1, 1.25, 2}, headless and headed:

1. **Launch A** captures references for every style a/b/c on the baseline state: the four-button toolbar and the
   wide toolbar, through the production `captureCandidates` (one screenshot per fan-out), then closes the browser.
2. **Launch B** is a fresh browser. For each style, target 0-3 and scenario it runs one fan-out over the toolbar and
   replays every candidate as the DOM best through the real `decideVisualAgreement` in `shadow` and `enforce` mode,
   against both the cross-launch reference (A) and a same-launch reference (B).
3. The DOM side is **synthesized**: a local `below-threshold` refusal with the best at score 0.70, ancestry 0.80,
   margin 0.08. N3.2 calibrates the visual half; the real DOM refusal is wired in N3.3.
4. Each wide-toolbar cell runs baseline and twins three times, with 8 competitors.

The "true" element is the remembered position, except under `swap`, where it is the neighbour that now carries the
remembered icon. Identity is exact pixel identity of the element crop (`contentDigest`); the 24 px context crop is a
separate `contextFingerprint` that the agreement policy does not read, so context padding cannot affect these
numbers.

The `--json` results file was **not produced**: the repository's command guard refuses extra arguments to npm scripts,
so the numbers below are transcribed from the console report of two complete runs. Decision counts were identical in
both runs; only timings differed.

## Recall

The true element, offered as the DOM best, reaches `agreed`:

| Reference | `baseline` | `drift` |
|---|---|---|
| Cross-launch (A) | 66/72 | 65/72 |
| Same-launch (B) | 72/72 | 71/72 |

Every miss is headless DPR 1: cross-launch 6/12 baseline and 5/12 drift lost (styles b and c, plus style a target 0
for drift); same-launch only drift style a target 0. Every other cell is 12/12. Wide toolbar with 8 competitors:
17/18 `agreed`.

So identity survives a fresh launch, a renamed target and 8 competitors well enough to be useful — **except** in
headless DPR 1, where the same element re-renders with different bytes across launches.

## False `agreed`

| Population | `agreed` |
|---|---|
| DOM best ≠ the true element, every scenario | **0 of 4644** |
| Plan acceptance: `swap`, `twins`, `restyle-*`, DOM best on the remembered position | **28** — all `twins`, all headless |
| … cross-launch | 17 (headless DPR 1: 8, 1.25: 3, 2: 6) |
| … same-launch | 11 (headless DPR 1: 2, 1.25: 3, 2: 6) |
| … headed, any DPR | 0 |
| Wide toolbar `twins`, 8 competitors | 3 of 18 |
| `swap`, `restyle-*`, `theme-*` with the DOM best on the remembered position | 0 (all `not-identical`) |
| `swap` with the DOM best on the neighbour carrying the remembered icon | 84 of 144 — the true element, so these are correct |

The plan's acceptance is "false `agreed` = 0 on swap, twins and restyle". Swap and restyle meet it; **twins does
not**. Under `twins` every button shows the remembered icon, so the honest answer is "the picture cannot tell them
apart" — A8 exists to refuse exactly that, and it only works if identical pictures produce identical bytes.

## Root cause: headless twin identity

Pairs of twin buttons whose crops are byte-identical, per cell:

| Cell | Four-button (pairs) | Wide (pairs) |
|---|---|---|
| headless DPR 1 | 0/72 | 66/108 |
| headless DPR 1.25 | 36/72 | 48/108 |
| headless DPR 2 | 12/72 | 18/108 |
| headed, every DPR | 72/72 | 108/108 |

Headless Chromium rasterizes the same icon differently depending on its position, so two visually identical twins
are frequently *not* byte-identical. A8 then sees "no identical competitor" and A9 agrees, on a page where the
picture genuinely cannot distinguish the target. Headed rendering is position-stable and produced no false `agreed`.
Unattended runs are typically headless, so this is not an edge cell.

Exact identity is the only signal N3.1 trusts (VR-2); loosening it to a similarity threshold would reopen the N2.3
finding that similarity does not separate swaps from restyles. There is no measured setting that keeps twins safe in
headless, so the pre-agreed fallback applies.

## Cost

`captureCandidates` + evidence + `decideVisualAgreement`, per decision, against FD-5's 400 ms:

| Run | 4 candidates p95 | 9 candidates p95 | Notes |
|---|---|---|---|
| 1 | 159–278 ms | 244–367 ms | every cell within FD-5 (worst: headless DPR 2) |
| 2 | 159–278 ms, except headless DPR 1: 516 ms (max 852) | headless DPR 1: p95 = max 2427 ms | outliers in one cell |

The policy itself costs ≤ 0.9 ms and peak temporary memory stayed ≤ 9 MiB. Cost is not the reason N3 closes
shadow-only, but the headless DPR 1 run 2 spike means FD-5 would have to be re-measured before any enforce work.

## Structural checks

All passed in both runs: no interaction with the page (no click, fill or hover), exactly one screenshot per fan-out,
the drift DOM changes present on the target only, `shadow` never returns `proceed`, every `shadow` `agreed` maps to
`enforce` `agreed`/`proceed`, and every cell was measured.

## Outcome

- **N3 closes shadow-only.** `awkit-vra.4.4` (enforce) and `awkit-vra.4.5` (provenance) are deferred by this recorded
  N3.2 outcome, which satisfies acceptance criterion 1 of the N3 plan.
- N3.3 still ships the shadow `agreed` verdict in `trace.visual`, so real-run recall and twin behaviour can be
  observed without affecting execution. N3.6 reconciles state and docs.
- Reopening enforce needs new measurements that show false `agreed` = 0 on twins in headless (for example a
  position-independent capture, or competitor identity measured another way) **and** a fresh owner decision. VR-0
  stays recorded, but nothing in N3 uses it.
