# L10.0 — DOM-intelligence incremental-value gate (2026-09-30)

Beads `awkit-djnl.18` (L10). Plan: `../L10-deterministic-dom-intelligence.md`. Data:
`L10.0-dom-intelligence-results.json` (this folder). Decision record: `docs/ai/DECISIONS.md` ›
2026-09-30 L10.0.

## Decision

- **Locator integration gate: NO-GO**
- **DOM normalization gate: NO-GO**

Both decisions follow from the rule in `scripts/dom-intelligence/gate.mts`, committed in `8072804a`
**before the first benchmark run**. `npm run verify:dom-intelligence-gate` re-derives both decisions
from the committed data. Nothing was wired into production. No Scrapling, Python runtime or host ships.

- **Locator.** Across the 13 recoverable cases, Scrapling found the target that AWKIT's recovery missed
  in 5. Only 1 of those candidates passes AWKIT's unchanged 0.86 / 0.08 gates (decision DI5), and in
  that case AWKIT's own scorer would also have found the target if its scan were not capped at 200
  elements. Scrapling also returned a wrong unique element in 6 of 16 cases, including all 3 cases
  whose correct answer is "no match". One of those wrong candidates would pass the unchanged gates.
- **Normalization.** Scrapling's static text leaks CSS-hidden and `[hidden]` content, because a static
  parse cannot see computed styles. The browser's own `innerText` leaks nothing, keeps every required
  fact, is smaller, and needs no new runtime.

## Method

- **Fixtures.** `scripts/dom-intelligence/fixtures.mts` holds 16 frozen baseline/mutated page pairs
  (13 recoverable, 3 whose correct answer is "no match"), a normalization page with canaries, and a
  synthetic DOM-size series. Every page's SHA-256 is recorded in the results.
- **AWKIT, three ways, through the production code.** The real Recorder init script captures the
  action on the baseline, and `buildRecordedFlow` assembles the step and its `PageBlueprint`. Winner
  memory is seeded by a real first resolve. Then `LocatorFactory.resolve()` runs on the mutated page as:
  - `production`: the recorded locators plus remembered-winner local recovery plus blueprint recovery;
  - `localOnly`: every recorded candidate forced to miss (a benchmark-only anchor attribute that
    AWKIT's fingerprint never reads), local recovery only;
  - `localAndBlueprint`: the same forced miss, then local and blueprint recovery.
- **Scrapling 0.4.15, parser-only.** `Selector.relocate()` runs on the element dictionary of the same
  baseline element, taken from the same `page.content()` HTML. Relocation is in memory, so
  Scrapling's storage is never used. The top candidate is mapped back into the browser by its XPath
  (all 16 mappings agreed with the host's verdict) and re-scored with AWKIT's own fingerprint: its
  identity score against the remembered fingerprint, and the best score of every other visible
  element (the margin competitor).
- **Environment.** Windows 10 x64, Node v18.16.0, Playwright 1.61.0 with bundled Chromium, Python
  3.12.10 in an isolated dev venv (`npm run benchmark:dom-intelligence-setup`).
- **Changes after pre-registration, disclosed.** No fixture HTML and no rule changed.
  - `field-relabel` is recorded as a fill, because clicking a `<textarea>` records no action.
  - The report prints the recorded alternatives.
  - The host reports the license's first line and a site-packages-relative path.
  - The outcome matrix was identical in all three complete runs; timings are given as ranges.

## Why the locator gate is NO-GO

- **The only gated gain is a coverage gap in AWKIT, not a better algorithm.** In `large-dom-shift`,
  the target sits beyond the 200-element visible scan. The inserted rows also move the page's tag
  histogram below the blueprint's 0.85 document-fingerprint gate. AWKIT's own scorer still rates the
  target 0.975, against 0.725 for the best other element. A wider native scan recovers it with no new
  runtime; the results' `analysis.incrementalGatedAlsoRecoverableByUncappedAwkit` lists it.
- **The other four gains fail the unchanged gates**:
  - `text-drift`: 0.833, below the 0.86 threshold;
  - `field-relabel`: 0.610, below the threshold;
  - `duplicate-text-decoy`: a margin of 0.042 over the decoy;
  - `list-item-link`: a margin of 0, since every "View" link has an identical AWKIT fingerprint.
  Accepting them means trusting Scrapling's own score, which DI5 rules out.
- **Scrapling always answers.** `relocate()` returns the top-scored element whenever it clears 40%.
  So it picked a wrong element in all three no-match cases, and in three recoverable ones:
  `wrapper-insertion` (AWKIT got it right), `aria-retained` and `combined-drift`.
- **The strongest case for Scrapling (post hoc, not a basis for the decision).** On these 16 cases,
  every correct Scrapling pick scored at least 86.67% and every wrong pick at most 80.32%. A threshold
  in between would have given 5 incremental recoveries and no false candidates. That result does not
  change the decision, for three reasons:
  - It is a threshold chosen after seeing 16 cases, with a 6-point gap.
  - It would replace AWKIT's gates with Scrapling's, which contradicts DI5.
  - The signals behind those five wins need raw DOM values persisted: `SequenceMatcher` partial string
    credit on text, `href`, class strings and parent text. AWKIT's privacy-hashed fingerprint cannot
    supply partial string similarity (see *Privacy*).

## Existing AWKIT defects found by this benchmark (independent of Scrapling)

1. **The viewport tiebreak selects the wrong duplicate** (`duplicate-text-decoy`, production). The
   recorded `role=button [Save changes]` matches two visible, enabled buttons after a same-label panel
   appears. `LocatorFactory.narrowToActionable` then keeps the one in the viewport, which is the decoy
   above the fold. The recorded target is below the fold.
2. **Unguarded positional alternatives select another row** (`list-item-link`, production). After
   the `href` changed, the recorded primary `css=a[href="/orders/1045"]` misses. Its alternatives
   `tr:nth-child(6) > td:nth-child(5) > a:nth-child(1)` (twice) then resolve, uniquely, to a different
   order's "View" link after the rows were re-sorted.
3. **Local recovery accepts a same-label element in another region** (`other-region-decoy-target-removed`,
   every AWKIT configuration). With the edit form removed, the identical "Save changes" button in a
   notifications panel scores 0.908 against the remembered fingerprint, with the next element at
   0.408. Tag, role, name and text together weigh 0.80 of `similarity()`, so any same-label element
   clears 0.86 once the original is gone. Sensitive steps refuse local recovery; non-sensitive steps
   click the decoy.
4. **The recovery failure path is slow** (observation). A forced-miss `resolve()` took a p50 of
   1.8–2.3 s and a p95 of 3.9–12.4 s. The two layers score elements one Playwright round trip at a time
   (up to 200 in local recovery, and a 49-element window with three round trips each in the blueprint
   layer).

These are recorded in `docs/ai/KNOWN_ISSUES.md` and tracked in Beads. No product code was changed by
L10.0.

## Runtime and packaging decision

Applies **only if** a future owner decision reopens L10 with a GO. Nothing is built now.

| Criterion | Embedded CPython (python.org embeddable) | Frozen executable (PyInstaller/Nuitka) |
|---|---|---|
| Offline, no admin | yes: an unzipped folder, with no installer or registry | yes |
| Startup | measured ~0.34–0.6 s cold (venv CPython) | onefile unpacks to `%TEMP%` on every start, which is slower and writes outside the approved roots; onedir matches embedded |
| Size (estimate, not a built package) | ≈ 7.2 MB runtime DLLs + ≥ 5.2 MB stdlib actually loaded (143 modules) + 13.2 MB site-packages ≈ 25 MB uncompressed | similar, plus the bootloader |
| Supply chain | pinned zip hash plus pinned wheel hashes, each auditable | a build-tool step that re-bundles everything, so harder to audit |
| Windows portability, AV | plain signed python.exe | onefile bootloaders are frequent AV false positives |
| Crash isolation | a separate child process owned by main (`utilityProcess` runs only Node) | same |
| Maintenance | patch = swap the pinned zip or wheel | patch = rebuild the frozen binary |

**Chosen if ever needed:** embedded CPython, pinned by hash, run as a main-owned child process with
the parser-only site-packages trimmed of `fetchers/`, `spiders/` and `engines/`. It would be the
product's first Python runtime, so the `src/offline/**` manifest, packaging and security slices are
Risk-3 and lease-gated.

## Privacy: the required design if L10 is ever reopened

- **Stripping before the host is mandatory.** `page.content()` of the normalization page carried every
  canary across a would-be process boundary, including the password and card values, which were set
  as `value` attributes. Values, hidden and template content, scripts and comments must be stripped in
  the page before any HTML leaves the browser.
- **Scrapling's reference record is raw.** It stores every attribute (including `value`, `href`,
  `style` and `on*`), raw text, raw parent attributes and text, the tag path, and sibling and child
  tags. Its scorer then runs `SequenceMatcher` over those raw strings. A hashed record, like AWKIT's
  fingerprint, removes exactly the partial-string signal behind Scrapling's wins here.
- **What any store would need.** An adaptive store would need an AWKIT-owned allowlist:
  - tag and role;
  - bounded, redacted text;
  - safe `id`, `name`, `type` and `aria-*` values;
  - `data-testid`;
  - class tokens with utility and hashed classes removed;
  - tag-only ancestry and siblings;
  - an `href` path template.
  It must also:
  - redact with `SecretMasker` and `SemanticRedactor` only;
  - bound every field and the whole record;
  - live under `%LOCALAPPDATA%/SpecterStudio`, never the package directory;
  - be invalidated by the locator approval binding;
  - never record protected-login, MFA, OTP, passkey or device-approval surfaces.
  That is a persisted raw-DOM-derived store, a new privacy cost that the hashed fingerprint deliberately
  avoids.
- **`ariaSnapshot()` needs the same care.** It exposes textbox values, including the password field,
  so any future normalization built on it needs the same value stripping.

## DOM normalization detail

| Method | New runtime | Leaked canaries | Missing facts | Output chars | ms |
|---|---|---|---|---|---|
| Scrapling static text (`get_all_text`) | yes | HIDDEN-CSS, HIDDEN-ATTR | none | 196 | 0.4 |
| Browser `document.body.innerText` | no | none | none | 116 | 8.4 |
| Playwright `ariaSnapshot()` | no | PASSWORD, card number | none | 590 | 29.6 |

`innerText` is the only clean method, but it flattens structure (form labels run together). A
structured, in-browser normalizer (an accessibility-tree walk with values stripped) needs no Python.
It is not part of L10 as registered.

## If L10 is to be reopened

A new owner decision is needed. Either of these routes could change the outcome:

- **Accept a second identity signal.** Score candidates with Scrapling-style partial-string and path
  signals under their own threshold, which relaxes DI5, and accept persisting redacted raw fields. Then
  re-measure on a larger held-out fixture set, with the threshold frozen before the run.
- **Port the signals natively.** Add partial-string and path similarity to `locatorFingerprint.ts` in
  TypeScript, and widen or fix the scan coverage (the 200-element cap and the blueprint document
  gate). This needs no Python runtime and no fetcher code.
