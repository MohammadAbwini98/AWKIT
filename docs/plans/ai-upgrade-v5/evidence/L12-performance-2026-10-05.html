On 4 Oct, after the L12 benchmark, three more changes landed: the for-each loop from similar rows, the Turnstile detector fix and the security-review fixes. This page re-runs the same benchmark on today's code and compares it with the 4 Oct result and with the code before L12.

Method and limits

  • Command: npm run benchmark:dom-intelligence-l12, three times in a row on one Windows 10 machine, Node 18.16.0, Scrapling in its staged parser-only host. 11/11 acceptance checks each run.
  • The 4 Oct and pre-L12 ranges are the ones published in the 4 Oct before-and-after report. Today's run 3 is saved in docs/plans/ai-upgrade-v5/evidence/L12-acceptance-results.json; the 4 Oct version remains in git history at 33c924b2.
  • Not measured here: how long Element Spy takes to find similar rows and build the loop selector, the cost of the read-time challenge check on a Super User sign-in diagnosis, and the detector's extra selectors on each Recorder navigation. None of these is on the path a run takes when a lookup fails.
  • The three recoveries L12 added still rest on thresholds set from 3 lab fixtures. Zero wrong elements holds on this benchmark set, not as a general guarantee for real sites.
