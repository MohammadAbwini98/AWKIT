# N2.3 — Fusion calibration lab and measurement (`awkit-vra.12.3`)

Measured on 2026-10-12, Windows 10, bundled Playwright Chromium, against the N2.2 policy `decideFusion`
(`14e6b3c9`). The verdict: **the lab shows no separation, so R8 is disabled and N2 ships shadow-only (FD-9).**

## Lab

`/visual-intelligence/fusion`, the Visual Fusion Calibration Lab (`mock-site/public/visual-intelligence-fusion.html`,
documented in `mock-site/README.md`). It holds an icon-only toolbar of four 48x40 buttons that share role, accessible
name ("Item action") and ancestry, so only their icons tell them apart: the case fusion exists for.
`window.__fusionLab.setState({ scenario, target, style })` redraws it deterministically.

| Scenario | Plan case | What changes against the baseline reference |
|---|---|---|
| `restyle-selected` | F1 | Only the right button changes look (inverted, selected) |
| `restyle-pressed` | F1 | Only the right button changes look (darker, inset ring) |
| `theme-dark`, `theme-contrast` | F4 | Every button at once (page-wide restyle) |
| `swap` | F2 | The remembered button now carries its neighbour's icon; the neighbour carries the remembered icon |
| `twins` | F3 | Every button carries the remembered icon |
| `injectProtected(kind)` | F5 | An OTP, MFA, CAPTCHA or passkey surface on the page |
| `vf-offscreen-tool` | F6 | The target below the fold |
| `?embed=1` frame, `?popup=1` popup, another DPR | F7 | The conditions differ from the reference |
| fusion `off` | F8 | — |

## Method

`npm run benchmark:visual-fusion` (`scripts/benchmark-visual-fusion.mts`, informational, never a gate). For each
DPR in {1, 1.25, 2}, headless and headed, each style a/b/c and each target 0-3 (n = 72 per scenario):

1. capture the reference from the baseline target (`captureElement`, no context padding) and build its evidence;
2. switch the scenario, capture the DOM winner (the button in the remembered position) and its three competitors;
3. record c = best competitor score − winner score, in basis points, and replay the stored evidence through the real
   `decideFusion` in `enforce-veto` mode under the derived policy.

A positive c means a competitor now looks more like the reference than the winner does. A veto needs c ≥
`contradictMarginBp`.

## Raw distributions

c in basis points, n = 72 per scenario, all DPRs and both headed and headless pooled:

| Scenario | Wanted | min | median | max |
|---|---|---|---|---|
| baseline | — | −589 | −406 | −323 |
| restyle-selected (F1) | no veto | 2637 | 2925 | 3118 |
| restyle-pressed (F1) | no veto | 586 | 758 | 835 |
| theme-dark (F4) | no veto | −561 | −337 | −242 |
| theme-contrast (F4) | no veto | −516 | −292 | −212 |
| swap (F2) | veto | 323 | 463 | 619 |
| twins (F3) | no veto | −1 | 0 | 0 |

Winner score medians: restyle-selected 6665, restyle-pressed 8836, theme-dark 8283, theme-contrast 8078, swap 9577
(range 9380-9677). The swap winner still scores high: a different icon on the same coloured button is a small change
to the fingerprint.

The gap (smallest F2 lead minus largest F1/F4 lead) is between −2618 and −2795 bp in every DPR × headed/headless group,
so the overlap is not an artefact of pooling.

## Separation analysis

- The largest no-veto lead is 3118 bp (restyle-selected). The smallest veto lead is 323 bp (swap). **Not separated.**
- Even without restyle-selected, restyle-pressed (586-835) overlaps swap (323-619).
- A restyle of the right element can make a look-alike neighbour look more like the reference than the element itself.
  This is a property of the fingerprint, not a lab artefact, so no margin can tell F1 from F2 on this evidence.

## FD-9 outcome

Following the approved fallback, `MEASURED_FUSION_POLICY` (`src/visual/fusion/decideFusion.ts`) records:

```json
{"calibrated": true, "corroborateMarginBp": 500, "contradictMarginBp": 3618, "domDecisiveMarginBp": 1600,
 "minSizeRatioBp": 5000, "contradictionEnabled": false}
```

- `contradictionEnabled: false`: R8 never fires and N2 ships **shadow-only**. N2.6 (enforce-veto) is deferred by
  this FD-9 outcome, which the plan allows without blocking N2's shadow-mode closure.
- `contradictMarginBp` 3618 is the F1/F4 maximum plus the 500 bp safety gap. It is recorded so a re-measurement
  starts from the same rule, not as an enabled threshold.
- `corroborateMarginBp` 500 is the larger of the safety gap and (smallest F2 lead + gap), so R6 never corroborates
  a swap. R6 is reporting-only (FD-3).
- `domDecisiveMarginBp` 1600 and `minSizeRatioBp` 5000 are policy anchors, not measurements: twice the 0.08 DOM
  recovery margin, and half the reference's CSS area.
- `REFERENCE_REFRESH` is not measurable in this lab; it is set with the reference store. That store was moved out of
  N2.4 by the owner's re-scope and is N2.4b, to be filed.

Outcomes under that policy, replayed through the real `decideFusion` in `enforce-veto` mode: false vetoes 0; F2
vetoed 0 of 72 and corroborated 0; F1 contested 144 of 144; F4 mostly contested (corroborated 11 and 4); twins and
baseline identical where pixel-equal. `verify:visual-fusion` checks that the constant is frozen, calibrated, never
vetoes over 4000 generated inputs and turns the canonical contradiction into contested.

## Structural rows

All 62 rows PASS, at every DPR, headed and headless:

- F5: each of OTP, MFA, CAPTCHA and passkey gives `dom-only/protected-surface`;
- F6: the offscreen target gives `target-offscreen`, and the page is not scrolled (scrollY stays 0);
- F7: the frame copy, a different DPR and the popup each give `dom-only/conditions-changed`;
- F8: fusion off gives `unchecked/fusion-off`;
- the page's interaction counter stays 0: capture never clicks, focuses or scrolls;
- the derived policy never vetoes F1/F4 and never corroborates F2.

## FD-5 timing

Capturing the winner and three competitors took a median of 499 ms per evaluation, p95 1111 ms (min 285, max 1314).
That exceeds the 400 ms FD-5 budget with four separate element screenshots. **Recommendation for N2.4/N2.5:** take one
viewport screenshot per evaluation and crop it K + 1 times, instead of one screenshot per element.

## Real headed Ctrl+zoom (was NOT RUN for N0)

`npm run benchmark:visual-fusion-zoom`, a headed browser with `viewport: null` on a 2x display:

- Playwright's keyboard (`Control+Equal`) and Ctrl + wheel do not change browser zoom. An OS-level `Ctrl+=`
  (`WScript.Shell.SendKeys`) does: `devicePixelRatio` 2 → 2.2 (110%).
- Zoomed: CSS viewport 942x679, `devicePixelRatio` 2.2, `visualViewport.scale` 1, screenshot 1884x1358 (scale 2.0).
- Both viewport and element capture give `CAPTURE_UNAVAILABLE` ("the screenshot scale does not match the device pixel
  ratio"). Fusion therefore gives `dom-only/capture-failed`. A zoomed page is refused, never mis-cropped.
- The reset to 100% was confirmed (`devicePixelRatio` back to 2).

The N0 comment in `src/visual/geometry.ts` claimed the measured-ratio mapping covered browser zoom. It does not, because
Playwright's screenshot stays at the unzoomed ratio. The comment is corrected and the refusal is the measured
behaviour.
