# Task contracts

One JSON file per task, plus `active-lease.json` when a write lease is held.

Contracts are **JSON, not YAML**. The repository has no YAML parser in `dependencies` or
`devDependencies`, and adding one would itself be a `new_dependency` change — routed to the
Architect and Release specialists and reviewed against the offline boundary. A governance tool must
not open the boundary it exists to police.

## Files

| File | What it is |
|---|---|
| `<task-id>.json` | The contract. Schema: `docs/ai/routing/TASK_CONTRACT.schema.json`. |
| `active-lease.json` | The single active write lease. Absent means no lease is held. |

`active-lease.json` is **generated by the tooling, never hand-edited**. It is registered in
`tools/roadmap/lib/sources.mjs` as a declared blind spot: the dashboard does not parse it, because
the holder is mirrored into `tools/roadmap/assignments.json`, which is already the only source the
dashboard treats as authoritative for who is working on what.

## Commands

```bash
npm run agent:lease
```

```bash
npm run agent:lease-amend -- --add "src/storage/**" --reason "Persistence impact discovered"
```

An amendment **re-runs routing**. If the added paths are owned by another specialist, the lease is
released rather than widened and the work moves to whoever owns them — permissions never creep
outward from one agent's original grant.

## Retention

`docs/ai/HANDOFF.md` is already over 5,000 lines because nothing ever told it to stop growing. This
directory does not repeat that.

- A contract stays here while its task is open.
- When the task closes, the contract is **deleted**. Its durable record is the Beads issue, the
  `TASK_LOG.md` entry, and the commits — three places that already outlive it.
- `active-lease.json` is never deleted; releasing sets its `status` away from `active`, which the
  guard treats as no lease. It persists because the dashboard registers it as a source and asserts
  every source is readable. A released lease is not history worth keeping, so it is overwritten by
  the next grant rather than archived.

Contracts are execution mechanics. Beads remains the work, status and dependency source.
