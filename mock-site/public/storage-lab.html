Storage Lab

Browser storage that the visible UI can contradict. Every control writes to localStorage or sessionStorage and reports what it BELIEVES it did in storage-status — the point of the scenario is that the banner and the store can disagree, so an assertion that reads the banner proves nothing about the store.

Session round trip

Sign in to write awkit-session as a JSON blob carrying a token. Sign out removes the key entirely. Fake sign-in updates only the banner and never touches storage — the case that a UI-only assertion passes and a storage assertion must not.

Empty value vs missing key

Write empty sets awkit-empty to the empty string; Remove deletes it. The two states are different and a storage assertion must be able to tell them apart — an absent key reads as (absent), never as "".

sessionStorage is a different area

Write session-only writes awkit-scope to sessionStorage only. Reading the same key from localStorage must still report it absent, so the area selector is load-bearing rather than decorative.
