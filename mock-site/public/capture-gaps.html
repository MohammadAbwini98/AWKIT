Capture Gaps Lab

Four capture shapes that WebDriverUniversity exposed and no earlier fixture had. Each one produced a recording that looked fine and could not replay.

Drag where the source follows the cursor

The dragged element is repositioned under the pointer, so it — not the drop zone — is the topmost element at the release point. elementFromPoint therefore returns the drag ghost, and a recognizer that reads only the top hit sees "released on the source itself" and discards the whole gesture. This is how jQuery UI, react-draggable and SortableJS all behave; the pointer sortable in /drag-lab does not move its item, which is why it never caught this.

Clickable list items identified only by their own text

The list re-renders on a timer with the SAME items in the same order, so a positional selector survives by luck rather than by identity. The wrapper carries the same aggregate text as its children combined — a container's concatenated text is a summary, not an identity, and must not be offered as one.

Clicked: idle

Readonly field that opens a picker

A readonly text input can never fire change or input, so a fill is never recorded for it. Clicking it IS the interaction — the way every datepicker and custom select is opened.

Picked: idle

Press-and-hold on a control the page replaces

The handler replaces the pressed element's contents on mousedown, so the node the press started on is gone before it ends. The browser fires no click at all in that case, so an unhandled gesture disappears from the recording entirely.
