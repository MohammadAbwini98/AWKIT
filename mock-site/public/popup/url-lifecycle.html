Scenario J — Popup URL lifecycle

Purpose: four cases where the popup's URL at creation time is not the URL that identifies it. The Recorder must register the page immediately, treat the provisional URL as provisional, and record the first meaningful committed URL as the popup's identity.

J1 — Opens at about:blank, then navigates

The popup is created blank and navigates 120 ms later. Reading the URL once at creation yields about:blank and loses the real identity entirely.

J2 — Redirects before the first interaction

The popup opens at /popup/redirect-entry.html, which answers 302 to /popup/redirect-final.html. The final URL is the identity; the intermediate hop must not be recorded as one.

J3 — Same-document URL changes inside the popup

The popup performs pushState and a hash change after load. These change the URL without a navigation, and must be attributed to the popup — never to this opener page.

J4 — Two popups, identical title, different paths

Both popups set <title>Shared report title</title>. Title cannot separate them; only the path can, so identity must not collapse to one page.
